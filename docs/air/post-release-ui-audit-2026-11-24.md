# Web UI consistency audit

24 November 2026 · Cloakyard, CloakPDF, CloakIMG, CloakResume, CloakDrop, CloakRoll and CloakTools

The compact Export control matches in all three web editors. On a phone it is an unfilled 18 px download icon inside a 44 × 44 px keyboard-accessible button. All three downloaded the expected file in light and dark. At desktop sizes the editors use the filled Export action. The Download buttons inside the PDF and image export dialogs confirm file delivery. Drop, Roll and Tools offer installation from their public sites. ## Release checks and limits

The Firefox public-page pass covered 756 landing layouts and 336 reading and recovery layouts in light and dark. Editor and tool coverage used Chromium and WebKit.

The hosted accessibility scan covered 168 Chromium configurations across the seven origins. It included 56 landings, 56 privacy pages, 24 workspaces, 24 dialogs and eight CloakTools installation views. The two compact light-theme Actions readings are documented above. Repeated checks covered 390 × 844, 768 × 1024, 1280 × 720 and 1440 × 900 in light and dark. The editor regression reached from 320 × 568 to 1920 × 1080. Browser emulation covered touch and mouse input.

The application suites passed 474 CloakPDF tests, 501 CloakIMG tests and 375 CloakResume production tests. The PDF browser smoke run exercised 18 workflows, including the retrieval interface, selection and annotations, search, tables, and export.

The dependency recheck covered 106 direct web declarations. It picked up Lucide React 1.79.0 for the directory, PDF and résumé, and LangChain Core 1.5.1 for PDF. All seven package audits reported zero known vulnerabilities. The three Astro sites use TypeScript 6.0.3, the latest release compatible with their current checker. The four Vite+ apps use TypeScript 7.0.2. [Astro checker peer range](https://registry.npmjs.org/@astrojs/check/0.9.12)

Physical devices, OS keyboards, spoken screen-reader output and cold model inference were outside the audit. The installed-worker check used a disposable browser profile. The PDF assistant states used a controlled model response. Automated accessibility results and selected screenshots cover the recorded views and states.

The deployed entry assets and 180 JavaScript and CSS files matched the production builds byte for byte. The source revisions are in the coverage ledger.
